# scriptc native compiler

scriptc is a native compiler written in Rust. Its source adapter links a pinned parser, binder and checker dependency; scriptc owns module planning, type layouts, lowering, IR validation and native emission. Dependency origins, revisions and licenses are recorded in `Cargo.toml` and `Cargo.lock`.

The pipeline is source → checked source frontend → scriptc IR v13 → native IR validation → Rust source → Cargo/rustc → executable. There is no TypeScript/Go compiler fallback and no JavaScript engine. Cargo and the Rust linker/toolchain are required to build output binaries. Primitive numeric formatting uses the Rust `ryu-js` crate, already fetched with the compiler dependency graph; output builds run offline.

## Architecture and phase boundaries

The Rust executable is the destination compiler. The previous CLI, checker bridge and emitters remain an explicit compatibility/reference path while coverage is migrated. Code generation never delegates a refused Rust build to that path. Developer commands are `pnpm build:compiler-rust`, `pnpm test:compiler-rust`, `pnpm scriptc:native --version` and `pnpm scriptc:legacy …`; `pnpm scriptc` retains its existing compatibility behavior until the distribution cutover is validated. Installed native programs use the Rust binary directly; pnpm/Node is only a developer launcher or test oracle here.

| Component | Responsibility | Boundary |
| --- | --- | --- |
| `project.rs`, source frontend | Load configuration, resolve source/types and check the selected project graph | All TypeScript diagnostics are checked, including unused function bodies |
| `frontend/pipeline.rs` | Own program-version scopes and sequence the checked/declaration/execution views | Only owned portable contracts cross checker versions; AST nodes/checker IDs never enter output IR |
| `frontend/modules.rs` | Build a module evaluation plan and native/JSON import bindings | Use the frontend resolver; preserve import/reexport order, cycles, side-effect imports and every module initializer |
| `frontend/functions.rs` | Inventory declarations and track demanded calls/function values | Deterministic IDs and FIFO fixed point; discovered → queued → lowering → lowered; expose signatures before lowering recursive bodies |
| `frontend/classes.rs`, `frontend/classes/` | Separate Error class identity, layouts, value uses and constructor demand | Preserve definition-time TDZ reads; initialize instance fields only after super; never erase unsupported definition-time effects |
| `frontend/types.rs`, `frontend/aggregates.rs` | Adapt checker types to owned value trees and intern record/union layouts | Array/map elements own their types; inline recursive layouts and function-valued array/map elements remain explicit refusals |
| `frontend/arrays.rs`, `frontend/helpers.rs`, `frontend/tuples.rs` | Lower dense array callbacks and tuple-entry Map construction to typed helper functions | Cache helpers by owned parameter/result layouts; preserve callback evaluation before length snapshot and materialize entries before insertion |
| `frontend/storage.rs` | Allocate program storage by resolved module symbol before initialization | Reexports and aliases share a binding; function locals and captures stay separate |
| `frontend/vars.rs` | Instantiate module/function var bindings and track definedness | Initialize once with undefined; keep source assignments in place; merge branch facts and invalidate mutable union facts at calls |
| `frontend/callables.rs`, `emit/functions.rs` | Adapt callable data objects and bound functions; emit traced function identities and lexical cells | Use existing record/function IR; preserve aliases, defaults and evaluation order; release named-function roots on exit |
| `frontend/declarations.rs`, `frontend/values.rs`, `emit/values.rs` | Link public JS function/class contracts and emit native erased payloads | Resolve implementation-only dependencies through a contract view; preserve owning handles; never evaluate source strings |
| `frontend/enums.rs` | Recognize constant compiled enum initializers | Preserve the hoisted namespace, ordered forward/reverse writes and namespace merging; refuse extra effects |
| `frontend/promises.rs`, `promise_values_support.rs` | Adapt standard Promise factories and fulfillment reactions | Preserve Promise identity and use the shared Rust microtask queue and adoption jobs |
| `frontend/union_literals.rs` | Select contextual literal union arms and read common fields | Transport owned record choices across checker versions; evaluate union receivers once |
| `ir/walk.rs` | Visit every owned expression and its temporary types | Exhaustive matches keep native ABI inventories complete as the IR grows |
| `frontend/regex.rs` | Adapt standard RegExp symbols and expressions to the existing regex IR | Use the shared Rust runtime; fresh literal identity and state belong to each instance |
| `frontend.rs` and lowering modules | Translate demanded source operations into typed native IR | Unsupported required operations fail with their demand chain; never catch-and-ignore an unsupported body |
| `ir.rs` | Own the serialized native contract and validate layouts, types, calls and initialization | No backend output before validation; cyclic value layouts are refused; Error object edges use traced identities |
| `emit.rs`, `emit/layouts.rs`, `emit/storage.rs`, `emit/collections.rs`, runtime Rust | Emit Rust operations with the IR's evaluation, aliasing and ownership semantics | No checker/AST dependencies or JavaScript source evaluation |
| `main.rs` | Parse build options, invoke the pipeline and Cargo, publish output | Offline native output builds; preserve previous output on failure |

Module initialization is a root of execution. Top-level function declarations are inventoried without constructing native signatures; a direct call or function value requests its ABI and body. Lowering a demanded body can request more functions, including mutually recursive functions. A referenced callback is conservatively considered executable even if its recipient happens to ignore it. Executable builds do not expose an external library ABI, so an unused export alone is not a root. Future library builds must supply their exported roots explicitly.

This is demand lowering of top-level function declarations, not general dead-code elimination. Initializers, imports, both branches of supported conditionals, closure expressions and class definitions are not deleted on assumptions of purity. An unused variable with an effectful initializer still runs; a referenced unsupported function still fails. Diagnostics include the call/value path from entry initialization that made the function required. Type errors remain errors in unused code.

The checked program and execution program can have different module graphs because package declarations and implementation exports resolve separately. Both use the same runtime-edge classifier; an entire `import type`/`export type` declaration is erased, while inline type specifiers may leave an empty runtime edge. Declaration contracts are owned data, never handles into the checked checker. Module evaluation order is planned once for the execution view before lowering starts.

## Migration sequence and retirement criteria

1. Establish explicit phase ownership, demand lowering, deterministic worklists and executable roots. Preserve module effects, type diagnostics and native/ref-backend differential tests. These boundaries are implemented in this checkpoint.
2. Generalize the native value/layout model. Owned array elements, arrays of records/unions/nested arrays, live module storage and traced records/maps are implemented. Source-checker IDs remain separate from native record/union IDs. Fixed required tuples and dense array map/Map seeds are implemented; broader tuple operations, union projections and cycle-capable source layouts remain to be ported; traced heap support alone does not establish their source semantics.
3. Add structured control flow and exceptions and broaden native Error classes and `unknown`/`any` value operations. Error construction, inherited fields and typed identity tests are implemented; Native erased payload storage and fixed generic function ABIs are implemented; throw/catch and general dynamic operations remain subsequent work. Representing JavaScript values in Rust must not introduce an interpreter or permit executing source strings as a fallback.
4. Add async/promise scheduling and the required Node APIs as native runtime operations. Build a capability inventory over the reachable program so project progress is measured by feature families as well as first refusals.
5. Make the Rust driver the distributed/default CLI after configuration, diagnostics, artifacts and representative projects satisfy the migration gates. Consolidate the IR contract into one authoritative schema with generated/checked language bindings before retiring the duplicate definitions.

The existing Rust runtime and differential corpus are retained. The TypeScript emitter/validator remains a test reference until native coverage replaces its contracts; it is not a production dependency of the Rust compiler. The TypeScript/TSGo bridge can be retired after native project/type/declaration contracts and the CLI cutover pass. C/LLVM and engine-backed lanes remain owned by the compatibility path until their product scope is explicitly retired. Native feature work belongs in the Rust pipeline; legacy edits should preserve compatibility/reference contracts rather than create a second native implementation. Existing pending work must be reconciled deliberately, not removed as dead code.

## Current native subset

Regular expression literals with gimsuy flags and standard `new RegExp(string, string?)` construction lower directly to the shared Rust regex runtime. Native test, source/flags reads, numeric lastIndex reads/writes, reference identity, typed containers and returned/passed regex values preserve aliases and fresh literal evaluation. Stateful global/sticky matching and UTF-16 index handling use the existing runtime implementation. The shared runtime now escapes delimiters and line terminators when serializing source, without changing the compiled pattern. Regex exec/match/replacement operations, general argument coercion, constructor copies from regex values and literal d/v flags remain outside this frontend subset.

Identifier var declarations are instantiated with a native undefined union before module evaluation or function-body execution. All module var slots initialize before any module body, including cycles; function-body slots initialize after parameter defaults. Source initializers remain assignments at their original location. Nested blocks share the function's var binding, bare redeclarations do not clear it, parameter redeclarations preserve the incoming binding, and captured slots use the existing shared boxes. Branches merge definedness conservatively; guards against undefined permit primitive/native projections. Calls invalidate facts for mutable union and erased vars, including calls lowered through contextual array helpers. A read that may still be undefined requires a compatible union ABI or a guard; it is refused at a strict value boundary rather than silently projected. Var destructuring, typed Map var slots and var/function declaration collisions remain explicit refusals.

Native Error objects use owned class identities and the shared IR v13 class/new/field/cast/instanceof contracts. Concrete non-generic class declarations and direct module-variable class expressions can extend the standard Error, TypeError, RangeError and SyntaxError families and other supported user Error classes, including imported/reexported bases. Constructors run on demand; an unused declaration's instance body or field layout need not have a native ABI, while the source checker still checks it. Reading a class as a value demands its constructor ABI through the shared classval/classRef/newValue contracts. Aliases, constructor parameters/returns and supported containers retain the exact class identity; native emission evaluates the constructor value before its arguments. Module class expressions execute once and use that definition's identity; local/repeated expressions and flows between different constructor identities remain refused. Definition-time base reads and class TDZ checks remain observable. Static/computed members, decorators, methods/accessors, abstract/ambient/local classes and arbitrary heritage expressions are refused rather than erased. Unions may contain one Error object arm; multiple class arms require cross-arm identity support and are refused.

Supported constructors have identifier parameters with native required/optional/defaulted slots, one unconditional top-level super call and no early returns. Implicit constructors forward the base ABI. Instance fields initialize after super, in declaration order, before the remaining body; declared fields without initializers carry undefined, and declare fields emit no initialization. Custom fields use typed undefined unions, and inherited field storage preserves the base prefix. Object handles retain identity through Error upcasts, checker-proven downcasts, arrays, aliases and traced cycles. Name/message mutation and Error.toString are native; cause/options, stack, general message coercion and throw/catch lowering are subsequent migrations. Reserved Error ABI metadata in the shared IR does not enable native dynamic values or an engine.

The current subset accepts `.ts`, `.mts`, `.js` and `.mjs` files with initialized `let`/`const` identifiers, primitive numbers/strings/booleans, numeric arithmetic and comparisons, unary minus/boolean negation, local assignments, blocks, boolean `if`/`else`, type aliases/interfaces and ambient `console.log`/`console.error`. Symbol identities preserve shadowed bindings. Non-finite numbers, negative zero and decimal literal spelling use the existing IR encoding.

Named top-level synchronous functions accept required, optional and defaulted native value parameters and native value/void returns. Direct calls, hoisting, recursion, mutual recursion and parameter reassignment lower to the existing IR `call`/`return` contract. Parameters retain their matching entries in the IR locals table. Optional/defaulted slots use existing undefined unions; direct calls, aliases and callbacks fill omitted slots with undefined. Defaults run lazily in parameter order inside the callee, with access to earlier parameters and fresh object creation per call. The body receives a separate mutable binding that closures can share. Optional/defaulted functions, defaults that may produce undefined, and parameter TDZ access remain explicit refusals. Flat arrays of strings, numbers and booleans can be created, assigned, passed and returned using the existing typed array IR; length and primitive indexed reads use existing IR operations; spreads, element mutation and array console inspection are later migrations. Indexed reads retain the existing native out-of-bounds trap policy.

ESM source imports use the Rust frontend's resolved module symbols, including config-relative paths aliases and package imports. Named/default imports, namespace function calls, re-exports and imported primitive values are linked across `.ts`, `.mts`, `.js` and `.mjs` source modules. Modules initialize once in DFS evaluation order, including cycles with hoisted function calls and initialized native values; reads before initialization are refused. `import type` dependencies are erased. Functions may call imported functions but cannot capture module variables yet.

The compiler discovers the closest `tsconfig.json` above the entry, or accepts `--project <file-or-directory>`. The upstream Rust parser preserves JSONC, `extends`, module resolution, paths, libs and Node/Bun type environments. Checking roots are the selected entry and project ambient declarations; executable dependencies are loaded by the resolver. Unrelated source/test roots are excluded. The native compiler overrides only `noEmit` and the checker worker count, and never edits the project. Invalid projects fail without fallback. Sources without a project use the standalone strict ES2022/ESNext configuration and a minimal mergeable console declaration.

For ESM packages that publish declarations separately from JavaScript, the public imports are typechecked first. A second Rust program resolves implementation exports with `noDtsResolution`, JavaScript loading and unrestricted package inference depth. That implementation AST supplies native lowering; unsupported bodies are refused. No user JavaScript is run during compilation. The `rust-native-package` differential fixture checks a `.d.mts`/`.mjs` package, aliases, module initialization and a local TypeScript dependency.

The two program views now share portable native function contracts. Matching the resolver's import/reexport edges connects declaration modules to runtime modules even when their package export paths and directories differ. Export aliases resolve to the actual implementation declaration; symbol names alone and guessed sibling filenames are never used as identity. Required/optional/defaulted native parameters and native returns and exported arrow functions retain their published signatures, including callback and record types. Locals with no recoverable execution-view type can derive storage from a successfully lowered initializer, with every subsequent use checked against that native representation. Conflicting declarations, overloads, unsupported public any/unknown types, arity differences and incompatible implementation bodies are refused. Untyped private helpers and JS control-flow refinements not supplied by the checker remain limited.

The `rust-native-js-contracts/contracts.ts` fixture is explicitly executed by the native compiler differential suite, including a runtime-backed callback and an escaping closure from unannotated JS. The old TypeScript frontend still requires an engine for this package shape. The IR interoperability test bypasses that old frontend, compiles the native IR with the existing Rust backend without engine features, and compares its binary to Node; this is a test oracle, never a production compiler fallback.

Default JSON imports can supply static string/number/boolean fields, including nested field reads such as `pkg.version`. General JSON aggregate values and mutations are refused until their native record/array representation is ported.

Closed, acyclic data records support nested object literals, required record parameters/returns, shorthand properties, reads, assignments and shared aliases. Structurally equal shapes are interned into the existing IR record layouts. Generated Rust uses traced `runtime::Gc` handles to preserve object identity and mutation; reads release their borrow before the next operand evaluates, and field initializers retain source order. Optional fields carry an undefined union arm and omitted literal fields retain the IR absence marker. Mixed declared/indexed shapes, recursive layouts, accessors/methods, prototype setters, record spreads and width projections between different layouts remain refused.

Native tagged unions represent supported primitive/record/primitive-array arms, including optional and nullable fields. Literal unions with the same primitive representation are widened to that representation. Explicit `null`/`undefined` comparisons, checker-proven single-arm narrowing, payload equality, boolean short-circuit operations and boolean conditional expressions use the existing IR union/logical/ternary nodes. General union subsets requiring re-tagging and standalone unit storage remain outside this subset. Optional typed arrays preserve shared identity and can be stored in fields, dictionaries and supported Map values. The `rust-native-records` fixture exercises BuildInfo-style returns, launch-probe-style nullable inputs and platform-style string domains without running any reddb application.

`Map<K, V>` and `ReadonlyMap<K, V>` share the existing typed map IR. Standard-library declaration identity prevents recognizing a user class by name alone. Native construction accepts empty maps, literal key/value pairs and dense arrays of fixed two-position tuple entries, including `new Map(array.map(callback))`; get/has/size, statement-position set, delete and clear preserve reference identity, replacement and SameValueZero numeric keys. Keys are string/number or native erased values; values can be supported scalars, records, arrays or unions, including stored undefined arms. Maps use a shared insertion-ordered typed vector in generated Rust (linear lookups); Map iteration, non-array iterable seeds, chained set results, function values and nested map values remain refused. Array seeds are consumed after the seed expression finishes; key/value projections use native coercions without reinterpreting array storage. No runtime engine is linked.

Pure string-indexed records (`Record<string, T>`) use the existing record indexValue/overflow/keyed-read/write contract. They can carry supported array/undefined unions and retain missing-value tags when the checker permits undefined (`noUncheckedIndexedAccess` or an explicit undefined value arm); a checker-proven value read retains the existing native missing-key trap. Dictionary aliases share storage and keyed writes evaluate object, key and value before borrowing. Hybrid/indexed-symbol shapes and inherited prototype behavior are not ported; accesses that require Object.prototype or dynamic prototype setters trap explicitly instead of manufacturing a native value. Records, dictionaries, arrays and maps use the shared traced heap. Generated tracing follows every typed owning edge; clearing drops record fields and container entries. Layout validation still refuses inline recursive source layouts and direct function elements in arrays/maps or dictionary values. Closed records can own functions; recursive callable signatures refer to records through the function ABI, while every function environment and shared lexical cell participates in cycle collection.

Dense `array.map(callback)` materializes a fresh typed array. The receiver and callback expression evaluate once, in order; the helper snapshots length after argument evaluation, reads each visited element at callback time and passes the value/index/source array slots requested by the callback. Inline closures, named function values, captured locals and defaulted callback slots are supported where their native signatures match. Appending during the callback does not extend the visit range. Variadic `push` evaluates all arguments before appending and returns the new length. Generated loops use existing IR `while`/array operations in cached typed helper functions; this does not enable arbitrary source loops. Sparse arrays, deletion/truncation, custom iterators/species and `thisArg` remain outside the native subset.

Fixed required tuples have the existing record `tuple` flag and exactly the positional fields `0..n-1`; their layouts remain distinct from numeric-keyed objects. Tuple literals, literal-position reads, readonly views and `length` preserve reference identity and evaluation effects. Optional/rest tuples, dynamic tuple indexing and function-valued tuple positions remain refused. The `rust-native-map-seeds` fixtures cover direct and stored entry arrays, callback factories, append/visit ordering, duplicate keys, SameValueZero, aliasing, empty input, nested map calls and escaping local captures.

Array element types are owned trees, with interned record/union identities. Arrays can contain records, tagged values and nested arrays; element reads clone the owning handle and preserve object identity and mutation through aliases. Builtin signatures are initialized once as owned data rather than borrowing leaked element types. The `rust-native-storage` fixtures cover records inside arrays, dictionaries and Map values, optional fields/elements, nested arrays and escaping local captures under heap auditing.

Module `let`/`const` bindings use the existing IR v13 `globals` namespace. An unconditional top-level assignment marked `initializesGlobal` in the entry initializes each slot; ordinary assignments require mutable storage and check TDZ even when they precede that declaration. The optional marker extends the existing v13 assignment node; legacy producers may omit it. All slots exist before module evaluation. Direct calls, recursion, callbacks, import aliases and reexports access the current shared slot rather than capturing its value. Uninitialized reads and writes throw a native ReferenceError, including through parameter defaults and cyclic imports. Slots are released on success and on unwind before the runtime heap audit; source initialization order and side effects remain governed by the module plan. Block/function bindings still use local/capture storage. Error tests compare the Node exit status, stdout and ReferenceError message; native stack formatting is not claimed to match Node.

The first native Node calls are `path` join/resolve/normalize/dirname/basename/extname/isAbsolute/relative (including explicit posix/win32 variants), `fs.existsSync`, `os.homedir`/`tmpdir`/`platform`, and `process.cwd`/`platform`. They use existing IR `libCall` nodes and the memory-safe Rust runtime with `default-features = false`; no island feature is enabled. Other registered builtin imports may be unused, but unsupported calls are named refusals. Loading Node/Bun declarations does not itself implement their runtime APIs.

Synchronous function values use the existing IR `func`, `closure` and `callValue` contract. Named function references preserve identity; anonymous arrow/function expressions create fresh closures. Captured native variables share traced lexical cells, including reassignment, escaping closures, function-valued captures and transitive captures. Functions have typed traced identities; named function slots are released with module storage before the final heap audit. Contextually typed lambdas can ignore trailing arguments and discard expression-body results for void callbacks. Closed function fields and supported undefined unions retain owning function handles. Named function expressions, forward lexical captures and general function-signature adaptation remain refused. Function signatures are owned compile-time type trees.

Nested function declarations, generic/async functions, rest parameters, CommonJS constructs, classes outside the supported Error hierarchy, general array operations, loops, async operations, general coercions, console format substitutions and lone UTF-16 surrogates are not ported yet. They produce TypeScript diagnostics or `SCN1001`; they never execute through another compiler or engine. Console calls with multiple arguments require a non-format literal when the first argument is a string. This executable does not yet compile the reddb applications or replace the existing CLI.

Native callable data objects use a private function field in an existing IR record, with public properties in typed fields. Object.assign can decorate a fresh anonymous function, a fresh bind result, or a const function binding whose only use is that decoration. After creation, aliases share the same property storage; Object.assign may update existing fields without changing the callable identity. Passing the value to a plain function ABI projects its function handle, preserving call behavior and equality with that view. An escaped bare function needs a shared extensible property representation and is refused; adding fields after escape, intrinsic function properties, own bind overrides, getters, prototype changes and fabricated callable records remain refused. Fixed generic function signatures and same-arity overloads can use native erased payloads. Generic callable data contracts retain a stable record layout with fixed native value slots and a recursive typed defaults factory. Erasing the entire callable data record to unknown still requires a shared extensible function property view and is explicitly refused.

Function.bind captures its target and fixed argument prefix once, left to right; a represented this argument is evaluated before the prefix, while literal null/undefined need no value slot. Source functions using dynamic this remain unported. Defaults run in the target when called, and bound functions receive fresh identities without copying the target's public properties. Required/optional fixed rest tuples produced by standard bind declarations are expanded in source position order at the ABI boundary; this does not enable source variadic function bodies. Function identities, property records and lexical cells use the shared traced heap, including cycles between a record field and a capturing function. The runtime crate itself is unchanged.

Compiled enum support recognizes module bare-var namespaces initialized by the standard anonymous IIFE with Enum || (Enum = {}). Its body must contain only string-member writes or safe-integer forward/reverse writes with literal keys and matching names. Initialization stays at its source site, reuses an existing namespace when declarations merge, preserves write order and reverse-name replacement, and retains undefined before initialization. Static forward/reverse reads and namespace aliases use typed dictionary storage; ordinary dictionaries remain distinct layouts. Extra initializer effects, dynamic keys, namespace reassignment/mutation outside that initializer, floating/dynamic initializers, non-module namespaces and direct source enum declarations remain explicit boundaries.

The rust-native-callables, rust-native-callable-contracts and rust-native-enums differential fixtures exercise the callable factory shape, recursive defaults, property aliases and updates, bind ordering/defaults, imported JS callable contracts, empty callback signatures, function-valued var slots, shared capture cells, collected cycles, merged compiled enums and reverse mappings. Production remains Rust from frontend to emitted binary, without an engine or compiler fallback.

Public class contracts now transport constructor slots and instance field layouts from declarations to JavaScript implementations, including fields introduced by `this.field = value` in constructors. The additional contract view roots execution sources and resolves their imports using normal package exports; implementation-only dependencies can contribute their own declarations. Native erased values use the existing dynFrom/dynCheck/dynCall/dynKeyGet/dynTest IR family and a generated Rust enum. Primitive payloads stay native; records, arrays, maps, compiled functions and Error objects retain their owning handles. Checks recover supported concrete representations, function calls dispatch to compiled Rust, defaults distinguish undefined from null/falsy values, and traced payload edges participate in cycle collection. Generic source function bodies still need supported native operations; this ABI does not add source evaluation, arbitrary object-layout conversion, source rest parameters or unrestricted prototype operations. Unsupported erased prototype members report an explicit runtime boundary. Erasing callable data properties is refused during compilation rather than discarding their function identity.

The `rust-native-erased` contracts cover generic identity and aliases, same-arity public overloads, public any parameters, transitive JS contracts, heterogeneous unknown payloads, optional ParseError-shaped constructors, constructor-assigned fields, inherited errors, checked optional-member narrowing, arrays, retained mutations, function identities and cycles. The original generic/unknown refusal examples that became supported remain as positive cases; unsupported generic rest bodies, function class fields and callable-property erasure retain boundary tests.

Polymorphic callable interfaces are canonicalized by declaration identity within one checker scope. Their call slots carry native values; named function properties retain compiled function ABIs, and a defaults factory returning the same generic interface returns that owned callable layout. Public schemas provide contextual result and function-value contracts to private JS helpers and bind prefixes. A demanded helper has one stable ABI; incompatible subsequent contexts are refused. Overloads with source rest/receiver slots and arbitrary extensible callable erasure remain outside this subset. Generic arguments never produce an unbounded series of source-checker-dependent record identities.

Untyped standard-library `new Map()` has native tagged keys and values. SameValueZero distinguishes primitive kinds, equates NaN keys and normalizes negative zero; object, array, function, Error and Map keys retain handle identity. Hoisted `var` slots for `Map<any, any>` store either the native Map handle or undefined, including module functions and reassignment through calls. Erased receivers use the existing dynInvoke IR contract for get/has/set/delete/clear; method lookup precedes argument evaluation, missing arguments become undefined, extra arguments are evaluated, and set returns the same Map for chaining. These operations dispatch to compiled Rust helpers. Typed Map var slots and Map iteration remain outside this subset. Native erased Map contents can form traced cycles without adding recursive inline layouts to the IR.

Plain object literals accept numeric property names using ECMAScript NumberToString, including hexadecimal/exponent spellings and numeric separators. Static string/numeric indexed reads and writes select closed record slots; supported dictionaries and erased objects also accept literal numeric accesses. Literal key conversion has no runtime effects, and receiver/initializer/value evaluation stays in source order. Arbitrary computed property declarations, effectful property-key coercion, record duplicates and prototype setters retain explicit boundaries. The rust-native-map-values and rust-native-property-keys fixtures compare native outputs to Node; they do not run any reddb application.

The reference Rust backend validates and emits the new Map IR, but its erased method dispatch does not yet implement Map methods. The reference also uses strict equality for erased Map keys, so NaN seeds do not have SameValueZero behavior there. Map contracts.ts, hoisting.js and seeds.ts therefore run as native Node differential programs and shared IR validation cases, without a reference-binary parity claim. Property-key contracts.ts additionally executes through the engine-free reference backend. All previously enabled reference-binary and source corpus cases remain enabled.

Standard-library Promise contracts now have an owned `promise<inner>` IR ABI. Synchronous source functions and stored callbacks can return native Promises, including the bundled-JS `var noop = () => Promise.resolve()` shape. Empty resolution fulfills with undefined; supported scalar, record, array, compiled-function and Error payloads retain owning handles. Resolving a represented Promise preserves its identity. Null uses an erased tagged payload, while undefined/void use the void fulfillment contract. Native payload storage uses the shared Rust Promise runtime and participates in heap tracing, including fulfilled Promise/record cycles.

Supported `.then` fulfillment reactions run through the Rust microtask queue after module evaluation. Each call produces a new Promise, absent/noncallable handlers pass the value through, callback returns are resolved into the result, and returned Promises use queued adoption. Native errors raised during reactions become rejections; rejection propagation and unhandled-rejection exit status use the shared runtime. This subset does not enable async source function bodies, await expressions, Promise executors, rejection callbacks, catch/finally, arbitrary thenable assimilation or the other Promise static factories. Known callable thenables are refused while lowering; erased thenables hit an explicit native boundary. No engine or compiler fallback is linked.

Contextual object-literal union selection now checks the actual source union arms while their checker is alive and transports only the selected owned record layout into the execution view. Common fields of supported record unions are read by a generated typed helper that evaluates the receiver once; checked narrowing can then select the arm for subsequent field reads. Checked snapshots carry only class-independent layouts. This preserves the ThemeAccent shape across JS dependency resolution without guessing from unrelated cached source types or discarding data fields. Unsupported ambiguous contexts, width projections and union member writes retain explicit boundaries.

The native type inventory exhaustively visits expression temporaries as well as storage and function signatures, preventing chained Promise expressions and inline payloads from losing their emitted native ABI. The rust-native-promises and rust-native-union-literals programs run against Node through both the native compiler and the engine-free reference Rust backend. Existing erased Map and custom Error reference limitations remain unchanged; all earlier test cases remain enabled.

Promise handle views in the shared Rust runtime now put their single strong source edge in a traced heap node. Catch/observe/poll hooks borrow that source weakly, and cloned handles trace their actual ownership of the edge node. This allows Promise/payload cycles to be collected while external aliases keep their source alive; the runtime regression test checks both sides of that contract.
