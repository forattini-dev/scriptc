# scriptc native compiler

scriptc is a native compiler written in Rust. Its source adapter links a pinned parser, binder and checker dependency; scriptc owns module planning, type layouts, lowering, IR validation and native emission. Dependency origins, revisions and licenses are recorded in `Cargo.toml` and `Cargo.lock`.

Module initialization is a root of execution. Top-level function declarations are inventoried without constructing native signatures; a direct call or function value requests its ABI and body. Lowering a demanded body can request more functions, including mutually recursive functions. A referenced callback is conservatively considered executable even if its recipient happens to ignore it. Executable builds do not expose an external library ABI, so an unused export alone is not a root. Future library builds must supply their exported roots explicitly.

This is demand lowering of top-level function declarations, not general dead-code elimination. Initializers, imports, both branches of supported conditionals, closure expressions and class definitions are not deleted on assumptions of purity. An unused variable with an effectful initializer still runs; a referenced unsupported function still fails. Diagnostics include the call/value path from entry initialization that made the function required. Type errors remain errors in unused code.

The checked program and execution program can have different module graphs because package declarations and implementation exports resolve separately. Both use the same runtime-edge classifier; an entire `import type`/`export type` declaration is erased, while inline type specifiers may leave an empty runtime edge. Declaration contracts are owned data, never handles into the checked checker. Module evaluation order is planned once for the execution view before lowering starts.

## Native API registry

`src/builtins.rs` owns native source API lookup and the typed library-call ABI used by IR validation and Rust emission. Its `builtins/` modules group Math, paths, filesystem, process, crypto and platform queries. Each public entry carries its lowering policy, argument/result bindings, Rust implementation, limited contract and differential evidence. `scriptc builtins` exports this registry as JSON and includes the existing String intrinsic table; `inspect` attaches registered port stages and contracts to direct builtin call requirements.

The stages are intentionally separate: `native-partial` means the listed frontend contract is executable, `runtime-only` means reusable Rust functions exist but the frontend contract is missing, and `planned` means no native implementation claim. The Bun entries describe dedicated adapters still to implement; BunFile, subprocess handles and CryptoHasher must retain their own source semantics. No Bun behavior oracle is claimed. This tracked-family registry does not replace the complete Node census in `internal/compatibility` or inherit its legacy/static or dynamic-engine support claims.

Source names and internal IR names are distinct. For example, the single `fs.mkdirSync` export selects four internal effect operations; `mkdirRecursiveModeSync` is never an invented Node export. Similarly, terminal properties select the internal `process.isTTY` helper without exposing a callable of that name on process. Module aliases such as `node:fs`, `path/posix` and `path/win32` resolve before source API selection.

Native import bindings preserve local source identity even when different modules share a checker declaration target. Mixed POSIX/Windows default imports and named aliases therefore retain their own path flavor. A declaration target with conflicting native registrations cannot be used as a forwarded shortcut; unresolved source provenance is refused rather than selected by import order.

Native `process.stdout.write` and `process.stderr.write` accept one primitive string with default UTF-8 encoding when their result is discarded, including contextually void arrow bodies. Global process declarations, native default/namespace imports and named stream imports use the same portable library calls. Writes preserve argument evaluation and do not add a newline. Stream objects or methods as values, mutations, explicit encodings, completion callbacks, error events and return-value/backpressure observations require separate contracts; the synchronous runtime sink does not establish Node stream queue semantics.

The first filesystem contract covers statement-only `mkdirSync` effects with represented string paths and numeric modes or plain inline recursive/mode options. Arguments, duplicate mode initializers and unused extras run before validation or I/O. Mode errors, existing/missing directories and null-byte paths have differential coverage. Result values, dynamic option objects, nonliteral recursion flags, accessors, iterable spreads and non-string paths remain explicit compile refusals; lone UTF-16 paths fail at the runtime boundary. Recursive first-created-directory return values, complete filesystem error fields and the remaining filesystem operations are separate ports. Test harnesses isolate the Node and native working directories for these fixtures.

`crypto.randomUUID()` has a zero-argument native binding with format/version/variant and fresh-value tests; the OS entropy source is Rust's getrandom dependency. Hash/HMAC handles and Buffer operations already present in the shared runtime are recorded as reuse candidates, not advertised as native frontend support. This avoids reimplementing the runtime while making the missing frontend adapters visible.

## Native standard library contracts

The native standard library is implemented as JavaScript semantics in Rust. Host containers are implementation tools: Rust `String` is not the JavaScript UTF-16 string contract, and an unordered `HashSet` is not the JavaScript Set ordering and equality contract. Reuse the shared `runtime-rust` values and operations; add a runtime operation only when its observable behavior is missing there.

| Layer | Responsibility | Evidence required |
| --- | --- | --- |
| Source frontend | Resolve standard declarations, argument/default conversions and syntax such as array spreads | Differential source programs, including shadowed names and evaluation order |
| Owned IR | Carry value layouts, identity, calls, exceptions and ordered construction | Native validation and interoperability with the reference Rust emitter |
| Rust runtime | Implement strings, numbers, collections and host APIs with JavaScript behavior | Runtime unit tests and native binaries compared with the pinned Node oracle |

Implement ECMAScript value families (`String`, numeric operations, `Array`, `Map`, `Set`, errors and promises) separately from host API families (`fs`, `process`, `crypto` and Bun APIs). A runtime implementation alone does not establish frontend support, and an accepted TypeScript declaration alone does not establish runtime behavior. The native API registry records those distinctions for its tracked families; it is not a claim that every builtin is complete.

Array literal spreads are construction syntax shared by ordinary arrays and Set/Map seeds. The frontend consumes each supported native array, string or fixed tuple before evaluating the next literal element, preserves shallow element identity, and builds through portable array operations. Strings iterate as UTF-16 code points, retaining lone surrogate units. Custom iterators, sparse sources, nullable/untyped sources and tuple-rest layouts require their own contracts and remain refused by this adapter.

Native primitive wrappers use zero-field class identities and internal ephemeron tables for their primitive payloads. `new Number`, `new String` and `new Boolean`, declaration-proven `instanceof`, and literal `valueOf` reads/calls share the portable class, WeakMap, function and receiver IR. Wrapper interfaces retain an owning tagged value because TypeScript also permits primitives in `Number`, `String` and `Boolean` slots. Constructor extras run before conversion; cached method values preserve identity and borrowed calls validate their receiver brand. Number/String object coercion hooks, constructor aliases, subclasses, prototype mutation, String exotic properties, implicit object conversion and direct wrapper JSON serialization remain separate contracts. Known unported wrapper property reads are refused; erased property reads fail explicitly rather than fabricate a value. This is a tested wrapper subset, not complete ECMAScript wrapper coverage.

## Migration sequence and retirement criteria

1. Establish explicit phase ownership, demand lowering, deterministic worklists and executable roots. Preserve module effects, type diagnostics and native/ref-backend differential tests. These boundaries are implemented in this checkpoint.
2. Generalize the native value/layout model. Owned array elements, arrays of records/unions/nested arrays, live module storage and traced records/maps are implemented. Source-checker IDs remain separate from native record/union IDs. Fixed required tuples, dense array map/Map seeds and guarded recursive record/union graphs are implemented. Broader tuple operations, unguarded recursive aliases and open JavaScript object projections remain separate contracts; traced heap support alone does not establish their source semantics.
3. Add structured control flow and exceptions and broaden native Error classes and `unknown`/`any` value operations. Error construction, inherited fields and typed identity tests are implemented; Native erased payload storage and fixed generic function ABIs are implemented; throw/catch and general dynamic operations remain subsequent work. Representing JavaScript values in Rust must not introduce an interpreter or permit executing source strings as a fallback.
4. Add async/promise scheduling and the required Node APIs as native runtime operations. Build a capability inventory over the reachable program so project progress is measured by feature families as well as first refusals.
5. Make the Rust driver the distributed/default CLI after configuration, diagnostics, artifacts and representative projects satisfy the migration gates. Consolidate the IR contract into one authoritative schema with generated/checked language bindings before retiring the duplicate definitions.

The existing Rust runtime and differential corpus are retained. The TypeScript emitter/validator remains a test reference until native coverage replaces its contracts; it is not a production dependency of the Rust compiler. The TypeScript/TSGo bridge can be retired after native project/type/declaration contracts and the CLI cutover pass. C/LLVM and engine-backed lanes remain owned by the compatibility path until their product scope is explicitly retired. Native feature work belongs in the Rust pipeline; legacy edits should preserve compatibility/reference contracts rather than create a second native implementation. Existing pending work must be reconciled deliberately, not removed as dead code.

## Current native subset

Recursive structural records, mutually recursive fields and recursive unions through record/dictionary/array handles retain stable owned layout IDs. The type adapter distinguishes resolving, ready and failed states and rolls back incomplete graph discoveries, including callable, class and module caches. IR validation accepts cycles guarded by native heap storage and still validates the remaining members. Bare recursive array/tuple aliases and ambiguous runtime union tags retain explicit boundaries. Closed recursive data records declared independently can share invariant views when their complete field graphs are equivalent. The comparison follows guarded record/union back edges, checks every sibling field and requires one unambiguous match per union arm. Native erased record tags use the same representative for equivalent closed layouts while the IR retains its declaration-specific IDs. Nullable source views retain null/undefined arms and remap tags without allocating or copying the object. Distinct recursive array/dictionary storage, nested field width changes and partial-union flow narrowing remain separate contracts.

The `rust-native-recursive-values` differential fixtures cover mutable/readonly JSON unions, public declaration-to-JavaScript function aliases, trees, optional mutual links, shared identity, cyclic heap cleanup, provisional empty-layout separation and checked reads after alias mutation. Four additional programs cover independently declared optional/mutual links, bidirectional alias writes, erased reads, width views and nullable/discriminated union remapping. Both Rust emitters retain owning views for this recursive structural subset; conversions do not serialize the graph or clone it to break cycles. Checked reference views track the active object/type pair during validation and recheck subsequent reads and casts after mutation.

Regular expression literals with gimsuy flags and standard `new RegExp(string, string?)` construction lower directly to the shared Rust regex runtime. Native test, source/flags reads, numeric lastIndex reads/writes, reference identity, typed containers and returned/passed regex values preserve aliases and fresh literal evaluation. Stateful global/sticky matching and UTF-16 index handling use the existing runtime implementation. The shared runtime now escapes delimiters and line terminators when serializing source, without changing the compiled pattern. Regex match operations, general argument coercion, constructor copies from regex values and literal d/v flags remain outside this frontend subset.

Identifier var declarations are instantiated with a native undefined union before module evaluation or function-body execution. All module var slots initialize before any module body, including cycles; function-body slots initialize after parameter defaults. Source initializers remain assignments at their original location. Nested blocks share the function's var binding, bare redeclarations do not clear it, parameter redeclarations preserve the incoming binding, and captured slots use the existing shared boxes. Branches merge definedness conservatively; guards against undefined permit primitive/native projections. Calls invalidate facts for mutable union and erased vars, including calls lowered through contextual array helpers. A read that may still be undefined requires a compatible union ABI or a guard; it is refused at a strict value boundary rather than silently projected. Var destructuring, typed Map var slots and var/function declaration collisions remain explicit refusals.

Native Error objects use owned class identities and the shared IR v13 class/new/field/cast/instanceof contracts. Concrete non-generic class declarations and direct module-variable class expressions can extend the standard Error, TypeError, RangeError and SyntaxError families and other supported user Error classes, including imported/reexported bases. Constructors run on demand; an unused declaration's instance body or field layout need not have a native ABI, while the source checker still checks it. Reading a class as a value demands its constructor ABI through the shared classval/classRef/newValue contracts. Aliases, constructor parameters/returns and supported containers retain the exact class identity; native emission evaluates the constructor value before its arguments. Module class expressions execute once and use that definition's identity; local/repeated expressions and flows between different constructor identities remain refused. Definition-time base reads and class TDZ checks remain observable. Static/computed members, decorators, methods/accessors, abstract/ambient/local classes and arbitrary heritage expressions are refused rather than erased. Unions may contain one Error object arm; multiple class arms require cross-arm identity support and are refused.

Supported constructors have identifier parameters with native required/optional/defaulted slots, one unconditional top-level super call and no early returns. Implicit constructors forward the base ABI. Instance fields initialize after super, in declaration order, before the remaining body; declared fields without initializers carry undefined, and declare fields emit no initialization. Custom fields use typed undefined unions, and inherited field storage preserves the base prefix. Object handles retain identity through Error upcasts, checker-proven downcasts, arrays, aliases and traced cycles. Name/message mutation and Error.toString are native; cause/options, stack, general message coercion and throw/catch lowering are subsequent migrations. Reserved Error ABI metadata in the shared IR does not enable native dynamic values or an engine.

The current subset accepts `.ts`, `.mts`, `.js` and `.mjs` files with initialized `let`/`const` identifiers, primitive numbers/strings/booleans, numeric arithmetic and comparisons, unary minus/boolean negation, local assignments, blocks, boolean `if`/`else`, type aliases/interfaces and ambient `console.log`/`console.error`. Symbol identities preserve shadowed bindings. Non-finite numbers, negative zero and decimal literal spelling use the existing IR encoding.

Named top-level synchronous functions and async functions without suspension accept required, optional and defaulted native value parameters and native value/void returns. Direct calls, hoisting, recursion, mutual recursion and parameter reassignment lower to the existing IR `call`/`return` contract. Parameters retain their matching entries in the IR locals table. Optional/defaulted slots use existing undefined unions; direct calls, aliases and callbacks fill omitted slots with undefined. Defaults run lazily in parameter order inside the callee, with access to earlier parameters and fresh object creation per call. The body receives a separate mutable binding that closures can share. Parameter TDZ access remains an explicit refusal. Flat arrays of strings, numbers and booleans can be created, assigned, passed and returned using the existing typed array IR; length and primitive indexed reads use existing IR operations; spreads, element mutation and array console inspection are later migrations. Indexed reads retain the existing native out-of-bounds trap policy.

ESM source imports use the Rust frontend's resolved module symbols, including config-relative paths aliases and package imports. Named/default imports, namespace function calls, re-exports and imported primitive values are linked across `.ts`, `.mts`, `.js` and `.mjs` source modules. Modules initialize once in DFS evaluation order, including cycles with hoisted function calls and initialized native values; reads before initialization are refused. `import type` dependencies are erased. Functions may call imported functions but cannot capture module variables yet.

The compiler discovers the closest `tsconfig.json` above the entry, or accepts `--project <file-or-directory>`. The upstream Rust parser preserves JSONC, `extends`, module resolution, paths, libs and Node/Bun type environments. Checking roots are the selected entry and project ambient declarations; executable dependencies are loaded by the resolver. Unrelated source/test roots are excluded. The native compiler overrides only `noEmit` and the checker worker count, and never edits the project. Invalid projects fail without fallback. Sources without a project use the standalone strict ES2022/ESNext configuration and a minimal mergeable console declaration.

For ESM packages that publish declarations separately from JavaScript, the public imports are typechecked first. A second Rust program resolves implementation exports with `noDtsResolution`, JavaScript loading and unrestricted package inference depth. That implementation AST supplies native lowering; unsupported bodies are refused. No user JavaScript is run during compilation. The `rust-native-package` differential fixture checks a `.d.mts`/`.mjs` package, aliases, module initialization and a local TypeScript dependency.

The two program views now share portable native function contracts. Matching the resolver's import/reexport edges connects declaration modules to runtime modules even when their package export paths and directories differ. Export aliases resolve to the actual implementation declaration; symbol names alone and guessed sibling filenames are never used as identity. Required/optional/defaulted native parameters and native returns and exported arrow functions retain their published signatures, including callback and record types. Locals with no recoverable execution-view type can derive storage from a successfully lowered initializer, with every subsequent use checked against that native representation. Conflicting declarations, overloads, unsupported public any/unknown types, arity differences and incompatible implementation bodies are refused. Untyped private helpers and JS control-flow refinements not supplied by the checker remain limited.

The `rust-native-js-contracts/contracts.ts` fixture is explicitly executed by the native compiler differential suite, including a runtime-backed callback and an escaping closure from unannotated JS. The old TypeScript frontend still requires an engine for this package shape. The IR interoperability test bypasses that old frontend, compiles the native IR with the existing Rust backend without engine features, and compares its binary to Node; this is a test oracle, never a production compiler fallback.

Default JSON imports materialize one owning native value per resolved asset, shared with statically resolved CommonJS requires. Object/array identity, nested values, root primitives (including negative zero), property mutations/deletion and module evaluation order reuse the native module cache. Reads observe the current value through aliases instead of folding mutable fields into constants. Namespace/named imports, JSON re-exports and JSON syntax outside the existing native parser contract remain explicit boundaries. The `rust-native-json-assets` corpus compares these contracts with Node through native binaries and the shared IR reference backend; no engine, runtime crate or IR version change is needed.

CommonJS `.js`/`.cjs` modules use the resolver's package format, separate module slots and compiled initialization functions. Literal `require()` calls in module initialization, including `if` branches and assignment RHS, execute at their original source sites and return cached `module.exports`, including partial exports in cycles. Replacing `module.exports` preserves the old `exports` alias; ESM default/named imports capture export snapshots. Unconditional module-level identifier require aliases for supported native builtins use the same native namespace linkage as imports; reassignment/redeclaration and escaping that namespace are refused. Required modules keep all initializers and class definition effects. Lazy/dynamic requests, requires inside loops/try or logical/conditional expressions, require of ESM, CommonJS namespace imports/reexports, module metadata and wrapper `this`/`arguments` remain explicit boundaries. CommonJS discovery does not make ordinary classes or the rest of a dependency's operations supported.

Literal CommonJS requests can also load JSON data through the same module cache. The parser keeps raw numeric spelling until JavaScript number conversion, preserves member insertion order with last-value duplicate replacement, strips the module-loader BOM and materializes nested objects/arrays and primitive roots as owning native IR values. JSON own properties such as `__proto__` are created as data rather than invoking a prototype setter. Repeated requests and cross-module aliases preserve identity and named-field mutations; inferred private JS object producers retain the data ABI. Lone UTF-16 surrogates and JSONC are refused. ESM and CommonJS share materialization; equality and presence reads retain property tags changed by aliases. Scalar uses that require a typed ABI retain their existing checked projection contracts. No JSON file is parsed by an engine at runtime.

`if` and unary negation use the native value truthiness operation, evaluating the tested expression once without invoking a function payload. Identifier presence tests read the live module/capture slot; nullable callback calls keep the tagged callee until argument evaluation and use compiled native dispatch. Positive Node/reference Rust cases cover callback installation/restoration, optional parameters, return values, mutable callbacks observed after another call, nullable array buffers, scalar truthiness and callback aliases. Typed Set erasure remains fenced; general non-boolean logical/loop/conditional-expression coercions and source try/catch are not implied by this support.

Closed, acyclic data records support nested object literals, required record parameters/returns, shorthand properties, reads, assignments and shared aliases. Structurally equal shapes are interned into the existing IR record layouts. Generated Rust uses traced `runtime::Gc` handles to preserve object identity and mutation; reads release their borrow before the next operand evaluates, and field initializers retain source order. Optional fields carry an undefined union arm and omitted literal fields retain the IR absence marker. Mixed declared/indexed shapes, recursive layouts, accessors/methods, prototype setters, general record spreads and width projections between different layouts remain refused.

Native tagged unions represent supported primitive/record/primitive-array arms, including optional and nullable fields. Literal unions with the same primitive representation are widened to that representation. Explicit `null`/`undefined` comparisons, checker-proven single-arm narrowing, payload equality, boolean short-circuit operations and boolean conditional expressions use the existing IR union/logical/ternary nodes. General union subsets requiring re-tagging and standalone unit storage remain outside this subset. Optional typed arrays preserve shared identity and can be stored in fields, dictionaries and supported Map values. The `rust-native-records` fixture exercises BuildInfo-style returns, launch-probe-style nullable inputs and platform-style string domains without running any reddb application.

`Map<K, V>` and `ReadonlyMap<K, V>` share the existing typed map IR. Standard-library declaration identity prevents recognizing a user class by name alone. Native construction accepts empty maps, literal key/value pairs and dense arrays of fixed two-position tuple entries, including `new Map(array.map(callback))`; get/has/size, statement-position set, delete and clear preserve reference identity, replacement and SameValueZero numeric keys. Keys are string/number or native erased values; values can be supported scalars, records, arrays or unions, including stored undefined arms. Maps use a shared insertion-ordered typed vector in generated Rust (linear lookups); Map iteration, non-array iterable seeds, chained set results, function values and nested map values remain refused. Array seeds are consumed after the seed expression finishes; key/value projections use native coercions without reinterpreting array storage. No runtime engine is linked.

Pure string-indexed records (`Record<string, T>`) use the existing record indexValue/overflow/keyed-read/write contract. They can carry supported array/undefined unions and retain missing-value tags when the checker permits undefined (`noUncheckedIndexedAccess` or an explicit undefined value arm); a checker-proven value read retains the existing native missing-key trap. Dictionary aliases share storage and keyed writes evaluate object, key and value before borrowing. Hybrid/indexed-symbol shapes and inherited prototype behavior are not ported; accesses that require Object.prototype or dynamic prototype setters trap explicitly instead of manufacturing a native value. Records, dictionaries, arrays and maps use the shared traced heap. Generated tracing follows every typed owning edge; clearing drops record fields and container entries. Layout validation still refuses inline recursive source layouts and direct function elements in arrays/maps or dictionary values. Closed records can own functions; recursive callable signatures refer to records through the function ABI, while every function environment and shared lexical cell participates in cycle collection.

Dense `array.map(callback)` materializes a fresh typed array. The receiver and callback expression evaluate once, in order; the helper snapshots length after argument evaluation, reads each visited element at callback time and passes the value/index/source array slots requested by the callback. Inline closures, named function values, captured locals and defaulted callback slots are supported where their native signatures match. Appending during the callback does not extend the visit range. Variadic `push` evaluates all arguments before appending and returns the new length. Generated loops use existing IR `while`/array operations in cached typed helper functions; this does not enable arbitrary source loops. Sparse arrays, deletion/truncation, custom iterators/species and `thisArg` remain outside the native subset.

Fixed required tuples have the existing record `tuple` flag and exactly the positional fields `0..n-1`; their layouts remain distinct from numeric-keyed objects. Tuple literals, literal-position reads, readonly views and `length` preserve reference identity and evaluation effects. Optional/rest tuples, dynamic tuple indexing and function-valued tuple positions remain refused. The `rust-native-map-seeds` fixtures cover direct and stored entry arrays, callback factories, append/visit ordering, duplicate keys, SameValueZero, aliasing, empty input, nested map calls and escaping local captures.
