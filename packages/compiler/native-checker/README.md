# TypeScript checker tuple serialization patch

The native checker is built from TypeScript 7.0.2's source revision `2bd066d87f5bafd315be9f40889d0a60b9e58e0b` in `microsoft/typescript-go`. Its API serialized some empty tuple references using `AsTupleType()` even though their data was a `TypeReference`. Querying such a reference directly or inside a union caused a panic. The patch reads tuple metadata from `TargetTupleType()` while retaining the original type's wire identity; tuple arguments, lengths, readonly metadata and union arms remain intact.

`pnpm --filter @scriptc/compiler build` builds and caches the patched server before compiling the JavaScript package. Development builds need Git and Go 1.26 or newer on PATH, or `SCRIPTC_GO_BIN` pointing to the Go executable. Go's normal toolchain acquisition policy still applies. `SCRIPTC_TSGO_SOURCE` may name a separate checkout at the pinned revision to reuse a local source tree. The build accepts only the named patch and does not reset an existing checkout. The server is built with `noembed` and shipped library declarations beside it because the virtual filesystem API needs real library paths.

The cache receipt records the source commit, patch digest, binary digest and library digests. A valid cache avoids rebuilding. The build also copies the server and libraries into the ignored `native-checker/bin/<platform>` distribution directory, which the compiler package includes. The loader checks a packaged server first, then the development cache. Explicit `SCRIPTC_TSGO_BIN`, explicit host options and the project's native-preview installation retain precedence. Without a prepared server for the host platform, the existing upstream server remains available, including its known tuple bug. Packagers must prepare each supported host platform; a build for one host does not supply other platforms' binaries.
